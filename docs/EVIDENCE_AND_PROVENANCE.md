# Evidence and provenance

Existing source evidence carries repository/parser identity, commit SHA, artifact identity, file/range, artifact content digest, exact quote and evidence identity. `rag/evidence.py::verify_git` checks stored artifact integrity, the complete artifact line range against the Git blob, and the quoted subrange. This prevents a matching short quote from hiding a forged artifact tail. Trailing line terminators are normalized by splitlines; artifact digests still refer to stored content. Git source checks do not establish semantic entailment.

Tool results carry `result_id = digest(policy, semantic envelope)`, excluding observation timestamp. Repeated identical observations reuse identity; changes in scope, input, facts, evidence or limitations change it. Retained lookup validates the envelope identity and rechecks sources. Retention is additive in tool_results; no old report is upgraded.

Unknown identity binds the tool policy, snapshot scope, code and question. Initial records point to their source result. Updates append a sequence with a prior fingerprint and expected_revision. Conflicts fail instead of replacing a head. RESOLVED requires a same-snapshot retained result with nonempty source excerpts and a note; it remains CALLER_ATTESTATION_SOURCE_LINKED. Source-backed resolution is not independent semantic review. Repeated observations do not reopen resolved records automatically.

Reviewed obligations keep their own append-only lifecycle and counterevidence. Optional `git_inventory` manifests enumerate all Git entries within declared prefixes, check object IDs and searched artifact identities, and reject UNKNOWN entries when completeness is attested. Exclusions require explicit rationales. Old histories retain their prior fingerprints when this optional field is absent. Machine enumeration verifies a declared boundary, not the truth of a reviewer judgment or whole-repository coverage. The template generator leaves every disposition UNKNOWN.
