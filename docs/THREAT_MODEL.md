# VIGILANT threat model — 26 October 2026

Status: **bounded local-service assessment; not a security certification**. This table records observed controls, evidence available in the repository, and residual work. A control is not marked verified solely because an implementation exists.

| Threat / asset | Current control and evidence | Status | Residual work |
| --- | --- | --- | --- |
| SSRF and redirect abuse during remote import | Exact HTTPS host allowlist for `github.com` and `gitlab.com`; credentials, nonstandard ports and ambiguous URLs rejected before Git starts. Git HTTP redirects disabled. `tests/test_input_audit_hardening.py`; `reports/import-security-20261026/focused-regression.xml`. | Focused behavior tested; no live redirect server | Pin/validate destination IPs safely or enforce outbound firewall rules; test DNS rebinding and redirects in an isolated network. |
| Path traversal and scope confusion | Local repository path is resolved and constrained to configured data roots. Analysis requests resolve repository IDs and commits. Partial-report source reads revalidate manifest, hashes and scope. | Focused tests exist; no complete race/tenant assessment | Test symlink replacement races, junctions/reparse points, report export path scope and multi-tenant isolation. |
| Malicious repository content and Git execution | Remote clone disables hooks, redirects, `file`/`ext` protocols and inherited/system/global config; clone runs in an isolated temporary cwd with no checkout. Git reads disable external diff/textconv. | Mocked clone policy and Git helper tests pass; no live remote clone | Execute hostile repository corpus, test Git version-specific behavior and verify no credential helper, filter or helper process runs. |
| Archive bombs | Repository import accepts Git URL or constrained directory, not arbitrary user ZIP/TAR upload. Release archives have separate manifest/hash verification. | User archive ingestion not in the current import API | Test generated release archives and any future archive ingestion separately; enforce decompressed byte, entry-count and depth budgets before extraction. |
| Resource exhaustion | Clone timeout/byte limits, request bounds, API job queue capacity and several source/output budgets exist. | Unit and bounded integration coverage; not a broad load test | Measure CPU, memory, file count, parser depth, concurrent job behavior, SQLite growth and large repositories. |
| Parser/compiler isolation | Repository parsers run inside the application process; no hostile compiler sandbox is established. | NOT VERIFIED | Disable compilers by default for untrusted content or use OS-level sandboxing and hard CPU/memory/time/network limits; test crash containment. |
| Authentication and authorization | Optional shared workspace bearer token uses constant-time comparison. Local mode remains available. Role-based and tenant authorization are not implemented. | Authentication behavior has focused tests; public/tenant deployment NOT VERIFIED | Test token rotation, secret storage, all export/source routes, authorization boundaries and session deployment policy. |
| Shared-token leakage | Token is read from environment and compared in middleware; no role model. | Bounded local control only | Audit logs/errors/process diagnostics, rotation, environment exposure and rate limits; avoid sharing across trust domains. |
| Secret exposure and sensitive source retention | Common secret patterns are withheld in selected evidence/report flows; exact source views intentionally display source to an authorized local user. Pattern matching is incomplete. | Focused patterns tested; completeness NOT VERIFIED | Run secret corpus, audit logs/cache/backups/exports, define retention/deletion policy and test redaction false negatives. |
| Report export access | API middleware covers non-public routes when a token is configured; partial-report reads revalidate manifest and source. | Bounded API tests; tenant isolation NOT VERIFIED | Test every JSON/CSV/HTML/export route under auth, foreign IDs, stale manifests and concurrent source changes. |
| Dependency vulnerabilities | Dependencies are pinned in project manifests. No fresh advisory scan is included in this checkpoint. | NOT VERIFIED | Run a current advisory scanner against pinned direct/transitive dependencies and retain the exact database/tool versions and output. |
| Injection through source artifacts | Source remains untrusted data; evidence spans are bounded and provider output is schema-validated. | Specific input audit tests exist; prompt-injection resistance NOT VERIFIED | Adversarial repository and prompt-injection review; demonstrate that source instructions cannot invoke tools, alter policy or become evidence. |
| Unsafe tool invocation | Tool calls use a bounded catalog, typed arguments and scoped evidence; unknown mutations are restricted by adapter policy. | Adapter tests exist; complete external-client/security audit NOT VERIFIED | Fuzz schemas, authorization, budgets, malformed MCP messages and cross-adapter behavior. |
| Multi-tenant isolation | The current service is a local/shared-token workspace and does not claim tenants or roles. | NOT APPLICABLE to the declared local mode; not safe to infer multi-tenant isolation | Do not deploy as multi-tenant until database, cache, reports, processes and authorization are isolated and tested per tenant. |

## Release decision

Keep public deployment blocked. This assessment does not verify DNS/egress controls, hostile compiler containment, a complete dependency scan, full secret detection, multi-tenant authorization, or broad load resistance. See `docs/SECURITY_MODEL.md` and the dated V026 report for the tested import boundary and its limits.
