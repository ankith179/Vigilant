# Acceptance criteria — 25 October 2026

These are release conditions, not claims of completion. Each task's bounded criteria and dependencies are in VIGILANT_MASTER_TASK_REGISTER.md. IMPLEMENTED is distinct from VERIFIED. A release may claim only the exact scope that passed recorded acceptance; exclusions must remain explicit and require review before scope is narrowed.

1. **Foundation and preservation.** Resolve archive/source identity, lease and processes. Retain every experiment, frozen snapshot, graph provenance, label, failure record and manifest. Verify all protected hashes and SQLite integrity; restore into an empty isolated directory. Never substitute an old upstream SHA for current working-copy identity.
2. **Revision and ingestion correctness.** Validate supported repositories and immutable commits. Report all files, exclusions, failures and partial coverage. Reject staged identities from full import before writes. Verify rename/move/delete/duplicate/branch histories; path-independent logical lineage remains a separate open acceptance item. Parser upgrades use a new identity.
3. **Graph, traceability, impact and consistency.** Keep declared, observed, inferred, candidate and confirmed status distinct. Bind edge endpoints and paths to exact revision/role. Preserve unavailable/out-of-page denominators. Do not infer causality from graph connectivity, completeness from extraction, or MISSING_TEST without reviewed obligations and reviewed search scope.
4. **Evidence and unknowns.** Revalidate source identity, full artifact hash, excerpt/range and retained result identity. Reject stale, foreign, malformed or sensitive evidence. Preserve conflicts/counterevidence and unknown histories. Source fidelity is distinct from semantic entailment and authenticated independent review.
5. **Application integration.** The production frontend must access real backend services and saved data. For the partial-report lane, test default-disabled behavior, pinned registry, catalog pagination, all 32 reports, full revision identity, 371 unknowns, graph endpoint/source navigation, line bounds, JSON fidelity, repeat selection, auth, stale/error handling and mobile overflow. Full investigation/chat/review lifecycle acceptance is tracked separately.
6. **Interfaces and reliability.** Exercise advertised CLI/MCP/API tools, schemas, errors, output/step/snapshot budgets and shared results. Verify persistence, transaction/concurrency behavior, queue capacity and restart recovery. User cancellation and an overall workflow deadline remain required open items. Production roles, tenancy and public deployment are not certified by local-token tests.
7. **Security, resources and platforms.** Maintain an explicit threat model and abuse-case tests. Check unsafe Git helpers, paths/URLs, redirects, subject execution, parser/compiler host access, prompt injection, sensitive source, authorization and resource controls. Record dependency scan date, actual hardware and repeatable latency/memory/load budgets. Fresh native Windows, clean Docker installation and broad hostile-input acceptance remain open.
8. **Independent scientific gate.** Obtain actual independent reviews/adjudication and suitable scoped gold, including unknown regions. Record all exposed/tuned projects. Freeze the pipeline hash, rubric, thresholds, repository/change-family-disjoint validation/final split and all denominators before final labels are inspected. Require at least 200 reviewed independent real-change cases and matching predictions. Report trace precision/recall/F1, consistency accuracy/macro-F1, impact and semantic support separately. Every missing/invalid/uncertain prediction remains under the declared denominator. All requested traceability and consistency metrics must independently reach 0.91; developer test-file Recall@10 and operational test counts cannot replace them.
9. **REA parity.** Verify each applicable operation's expected behavior against pinned source and actual runtime checks. Source contract inspection alone cannot establish parity. Scope exclusions/deferred operations remain visible. The current 410-row source inventory has no full parity pass.
10. **Research and final release.** Consolidate exact source/commands/results/failures in a reproducible release record, retain negative experiments, and update paper/thesis only for material verified findings. Independent review, institutional/venue details and explicit submission authorization remain prerequisites. Passing software tests or formatting a draft cannot establish publication readiness or acceptance.

The existing evaluation protocols remain DRAFT_NOT_FROZEN while the required independent data and approvals are absent. No artificial freeze, invented labels, easier replacement target or repeated final-test tuning is permitted.
